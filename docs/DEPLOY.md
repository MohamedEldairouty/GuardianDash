# ☁️ Deploying the backend so the app works without a laptop

The mobile app currently talks to a backend at `http://<laptop-ip>:4000`.
That means the laptop must always be on, same Wi-Fi, etc. For a real product
you want the backend on the **public internet** so the app works anywhere.

This guide deploys it to **Render.com** in ~5 minutes (free tier).

## Why Render?

- ✅ Free tier (no credit card required)
- ✅ Auto-deploys from GitHub on every push
- ✅ Persistent disk included (1 GB) — your SQLite DB survives restarts
- ✅ Free HTTPS subdomain (`https://guardiandash-api.onrender.com`)
- ⚠️ Free instances sleep after 15 min idle; first request after that takes ~30s
- ⚠️ Free Postgres expires after 90 days (but we're using SQLite, so n/a)

Alternatives (if you outgrow Render free): **Railway** ($5/mo), **Fly.io**
(generous free), **Supabase** (Postgres + auth), **Vercel** (serverless).

## Steps

### 1. Push your repo to GitHub (if you haven't)

```bash
cd D:\Prog\GuardianDash
git push -u origin main
```

### 2. Sign in to Render

Visit https://dashboard.render.com → "Get Started for Free" → sign in with
your GitHub account.

### 3. Create a new Blueprint

- Click **New +** (top right) → **Blueprint**
- Click **Connect a repository** → pick **GuardianDash**
- Render reads `backend/render.yaml` and shows the plan: 1 web service +
  1 persistent disk
- Click **Apply**

### 4. Wait ~5 minutes

Render builds the Docker image and starts it. When the dashboard shows
"**Live**" with a green dot, you're up. You'll get a URL like:

```
https://guardiandash-api.onrender.com
```

### 5. Verify

Open in any browser:
```
https://guardiandash-api.onrender.com/api/v1/health
```
Should return:
```json
{"ok":true,"name":"GuardianDash backend","time":1700000000000}
```

### 6. Point the mobile app at it

In `app/.env`, change to the new URL:
```
EXPO_PUBLIC_API_BASE=https://guardiandash-api.onrender.com
```

Restart Expo. From now on the app works **from anywhere**, on any Wi-Fi,
without the laptop being on.

## What about the bridge / live hardware data?

The bridge (`bridge/`) is still **per-laptop** because it talks to USB serial.
Two ways to make the hardware also work without a laptop:

1. **Add a Bluetooth module (HC-05 or BLE) to the STM32** → phone talks to
   the board directly via Bluetooth. See `hardware/WIRELESS.md`.
2. **Add an ESP32/ESP8266 WiFi module** → board pushes telemetry directly
   to the cloud backend over WiFi.

The mobile app's UI is wireless-ready — it already speaks WebSocket and the
LCD mirror updates from whatever telemetry source is hooked up.

## Updating after code changes

Just push to GitHub:
```bash
git push
```
Render auto-deploys within ~3 minutes. No CLI, no SSH, no Docker commands.

## Secrets

`GD_JWT_SECRET` is auto-generated by Render (`generateValue: true` in
`render.yaml`). It's strong and never visible in source. To rotate, go to
Render dashboard → Environment → Edit → generate new.

## Database backups

Render's free disk persists across restarts, but isn't automatically backed
up. For a school project that's fine. For production, run:
```bash
sqlite3 /data/guardiandash.db ".backup /data/guardiandash.$(date +%F).bak"
```
via a cron job (Render Cron Jobs are $1/mo).
